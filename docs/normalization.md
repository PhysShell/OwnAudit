# Normalization — SARIF in, one categorized findings set out

`aggregate/normalize.py` is the stage that turns each analyzer's SARIF into the
`findings.json` everything downstream reads (`report/`, `viz/`, `runtime/`,
`fix/`). It was ported here from the deprecated `Own.NET/audit/aggregate/`
(Own.NET#266, slice 1A). Before the port, `Run-Audit.ps1` shelled out to
`python $Worktree\audit\aggregate\normalize.py` — the audit repo could not
normalize its own findings without a second checkout on disk.

```
PYTHONUTF8=1 PYTHONPATH=. python3 aggregate/normalize.py \
  --sarif own-check=artifacts/ownsharp.sarif \
  --sarif codeql=artifacts/codeql.sarif \
  --sarif infersharp=artifacts/infersharp.sarif \
  --sarif roslyn=artifacts/roslyn.sarif \
  --strip SectorTS --strip C:/Repos/STS_new/SectorTS --strip /C:/Repos/STS_new/SectorTS \
  --json artifacts/findings.json
```

`--taxonomy` defaults to the shipped `aggregate/taxonomy/categories.json`.
`--selftest` runs the embedded checks with no live data.

## The three honesty rules

They are the reason this is a normalizer and not a `dict.get`:

1. **An unmapped rule is not dropped.** It lands in `uncategorized` (category 0)
   and its ruleId appears in `coverage.uncategorized_rules`, so the taxonomy grows
   because someone looked at the ledger — not because a finding disappeared.
2. **`OWN001` is an umbrella code, split by its `[resource: ...]` tag.** One
   ruleId covers IDisposable fields/locals, subscription tokens and timers. A flat
   `OWN001 -> category 1` would fold subscription and timer leaks into the
   IDisposable bucket and undercount both.
3. **Third-party findings are suppressed but counted.** A DevExpress finding is
   absent from `findings` and present in `coverage.suppressed_by`. So is an
   analysis-skipped `OWN050` note, under `analysis_skipped_by`. The ledger
   balances: `total - kept == suppressed + analysis_skipped`.

`coverage` is the honest half of the payload. Read it before believing a count.

## Why the taxonomy is JSON

The reference taxonomy was YAML, which meant `import yaml`. OwnAudit's Python
tooling is stdlib-only and CI installs no packages, so reading our own knowledge
base cannot be the one thing that needs a wheel. `aggregate/taxonomy/categories.json`
is a mechanical transcription; the prose that lived in YAML comments moved into
the file's `_doc` block (keys starting with `_` are documentation and are skipped
by the loader), and with an Own.NET checkout on hand the transcription re-verifies
itself:

```
PYTHONUTF8=1 PYTHONPATH=. OWNNET_REF=/path/to/Own.NET python3 aggregate/tests/test_normalize.py
```

Without `OWNNET_REF` that check is skipped — and says so on stdout, because a
skipped check that prints nothing reads exactly like a passing one.

## Parity: what "ported" is allowed to mean

The port's claim is byte-for-byte output identity, not "same idea". Two things
back it:

- **The committed fixture.** `aggregate/tests/fixtures/parity/` holds four
  hand-built SARIF inputs and `expected-findings.json`, which was generated by the
  *reference* implementation (see `PROVENANCE.md` there). `aggregate/tests/test_normalize.py`
  diffs the port's output against those bytes on every CI run, and spells out the
  semantics they encode so that regenerating the golden from a changed
  implementation cannot quietly redefine correctness.
- **The full corpus.** Both implementations were run over the recorded STS SARIF in
  `sts_audit/` — 73 397 results, 72 559 scored, 25.8 MB of JSON — and the payloads
  are identical:

```
SARIF="--sarif own-check=sts_audit/ownsharp.sarif --sarif codeql=sts_audit/codeql.sarif
       --sarif infersharp=sts_audit/infersharp.sarif --sarif roslyn=sts_audit/roslyn.sarif"
STRIP="--strip SectorTS --strip C:/Repos/STS_new/SectorTS --strip /C:/Repos/STS_new/SectorTS"

PYTHONUTF8=1 python3 /path/to/Own.NET/audit/aggregate/normalize.py $SARIF $STRIP \
  --taxonomy /path/to/Own.NET/audit/static/taxonomy/categories.yml --json /tmp/ref.json
PYTHONUTF8=1 PYTHONPATH=. python3 aggregate/normalize.py $SARIF $STRIP --json /tmp/port.json

cmp /tmp/ref.json /tmp/port.json     # byte-identical
```

Note that `sts_audit/findings.json` — the recorded artifact — is **not**
reproducible from the SARIF files committed next to it: it was generated from a
slightly different blend of the `*-sectorts` / `*-core` inputs (it differs by ten
category-14 findings and a handful of Roslyn CS diagnostics). That is an input
provenance gap in the recorded run, not a normalization difference; the two
implementations agree exactly whenever they are given the same inputs.

## What is deliberately still missing

- **A SARIF result with no usable location is dropped and counted nowhere.** That
  is the reference behaviour, preserved so the parity claim means something, and
  it is a real hole in a ledger that otherwise refuses to lose a finding silently.
  It is pinned by a test (`20` results read as `19`) so it cannot drift, and it
  gets fixed in a change that owns the payload difference rather than under a port.
- **No identity or provenance fields.** `pattern_id`, `occurrence_id`,
  `schema_version` and provenance belong to slice 1B. The test asserts the record
  has exactly ten keys, because a field that ships before it means anything is a
  field consumers start depending on anyway.
- **`score.py` / `report.py` have not moved.** `Run-Audit.ps1` still runs those
  from the Own.NET worktree. Normalization is the stage that had to come first —
  everything downstream reads its output.
